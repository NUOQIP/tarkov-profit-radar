# 数据来源与可行性核验

核验日期：2026 年 10 月 20 至 21 日。以下区分实际读取结果与仍需验证的限制，避免将第三方行情数据当成游戏成交记录。

## 2026 年 10 月 21 日真实行情接入

上一版交互草图只手选了 12 件物资，主要是交换品；价格、手续费与历史标签都是演示值。这不是数据源的分类限制。当前产品入口改为 `app/` 下的真实行情页面，旧草图保留用于追溯设计，不再作为行情使用。

北京时间 00:22 获取的 PVE 数据包含 5,480 个源对象。首次计算后有 4,454 项可显示有效出售估值，涵盖 11 类；其中武器 171、配件 2,314、护甲与头盔 195、弹药与投掷物 443、钥匙与门卡 242。数量包含商人回收估值，不等于均可上跳蚤。该时点查到 141 条直购和 39 条兑换的正收益估算；它们会随报价时效、设置和新快照变化，不能作为保证成交或保证库存的数字。

名称翻译需额外读取 `/{mode}/items_zh`，并用 `/{mode}/items_en` 回退；给 `items` 加 `lang=zh` 查询参数不会直接完成翻译。这与[提供方的请求实现](https://github.com/the-hideout/tarkov-dev/blob/main/src/modules/api-request.mjs)一致。

实际读取发现，部分单品的 `lastScan` 比接口获取时间早数小时。因此接口成功返回不代表每件物品都刚更新。当前页面区分近期报价、1 至 6 小时的延迟估算和商人底价；延迟报价可以显示在普通列表，但不进入短线、仅显示条件已确认和 QQ 摘要。实际成交、钥匙剩余次数、装备耐久、商人剩余库存仍需玩家核对。

真实版物品图直接使用 API 中的 `assets.tarkov.dev` 地址，没有通过相似物品图替换缺图。游戏图像和名称仍属于相应权利人。

因此，新应用参考其功能，但数据接入直接选择已验证的公开接口。若未来得到该站明确的来源说明，可补充结论。

## tarkov.dev

来源是社区项目，并非 Battlestate Games 的官方成交接口。[项目说明](https://github.com/the-hideout/tarkov-api)列出物品价格、交易、藏身处配方等能力。

直接请求 [JSON 接口目录](https://json.tarkov.dev/endpoints)成功，返回：

| 市场代码 | 本应用显示 |
| --- | --- |
| `pve` | PVE |
| `regular` | PVP 常规 |
| `pvp-season` | PVP 赛季 |

接口目录同时提供物品、兑换、制作、藏身处、商人、任务及单物品历史价格；支持 `zh` 语言。原始物品集合的名称字段是翻译键，正式应用必须处理对应翻译，不可直接显示键值。

本次读取结果：

- 三个市场的 `items` 均成功返回，PVE 物品集合为 5,480 条。该数量包含不能正常交易或获取的对象，不等于可推荐物品数。
- PVE `barters` 返回 855 条兑换配方，`crafts` 返回 214 条制作配方。
- PVE LEDX 样本有占格、基础价、当前低价、24 小时均价、报价数量、商人收购、更新时间和逐物品跳蚤等级条件。
- [PVE LEDX 历史接口](https://json.tarkov.dev/pve/prices/5c0530ee86f774697952d952)成功返回 963 个历史点，包含 `price`、`priceMin`、时间戳，近期点含 `offerCount`；不同历史区间粒度不同。
- 兑换含商人等级、限购、材料及任务解锁；制作含耗时、设施等级、产出数量及 `tool` 标记。

这些字段可以支持单格价值、兑换与制作计算。它们不能直接提供用户真实剩余库存、实际成交速度或完整活动可获取性。

当前读取的三个市场配置均为 `foundInRaidRequired: false`、全局跳蚤等级 15、两项手续费参数各为 0.05。LEDX 另有物品级条件 35，说明不能只检查全局等级。以上是本次接口状态，不应永久写死，实际游戏变更需重新核验。

手续费应参照[数据提供方前端的实现](https://github.com/the-hideout/tarkov-dev/blob/main/src/modules/flea-market-fee.mjs)，同时读取最新参数。源码中的兜底常量和当次数据参数可能不同，不能照抄兜底值作为现行规则；正式版需用游戏挂单界面的实例验证数量、减免和舍入。

价格的逐项 `lastScan` 应用于新鲜度判断。历史 `offerCount` 是报价观测，不能作为销量。建议按市场自建快照，保存成本和规则版本，才能分析可复核的历史净利润。

## 实施时优先补齐

2026-10-21 后续核验：LEDX、Chek. 15 钥匙、M855 弹药盒与显卡在最近 30 个完整 UTC 日中分别有 27、30、30、30 日满足至少 3 条报价的历史记录。它们可支持价格回算的长期高值标签，不能证明历史手续费或配对材料利润。

`tasks` 提供任务对象，`tasks_zh` 提供翻译；制作 214 条中有 31 条任务解锁、9 条需要特殊任务物品、1 条受游戏版本限制。工具标记为非消耗，水滤芯等材料数量可为小数。不能把商人的 `buyAllowed` 当作玩家可购买资格。

源数据未提供完整每工位电耗，也未为最低报价附带实际容量、耐久和钥匙余次，因此本应用使用明确的手填燃料分摊与成色提示。活动限定物品始终保留，显示由开关控制；源数据没有全面的活动可获取字段。

- 活动限定、常规刷新与不可获取物品的可维护分类及出处。
- 手续费与游戏挂单实例的一致性，以及各市场和角色条件。
- API 访问策略、数据与素材署名、结构变更检测及国内访问表现。
- 历史配方、商人价格、燃料和手续费版本；缺失区间不得称为精确历史利润。
- 市场最低扫描价与可执行买入成本的差异，以及异常低价、高价的过滤。

## 2026-10-21：预设、报价数量和弹药包复核

直接核对 [Wiki PVE 兑换表](https://www.eftarkov.com/exchange?mode=pve)及其公开加载数据：MRS 的材料为手摇钻 ×1、SurvL ×1，材料成本48,776，独立预设报价310,273，费31,713，利润229,784；SA58 AUT 为内存×3，成本45,000，独立预设报价233,333，费23,595。页面只输出计算结果，未公开服务端完整实现；不能由结果断言其后端代码细节。

同期 tarkov.dev 的 MRS 专属报价 `lastScan=2026-10-10T21:28:05Z`、数量1。它不是当前可执行的同型号普通整枪价。用户明确要求预设作为低价获取路线，出售按同型号武器计算，不另加配件收入。因此改为同型号 `defaultPreset` 的行情和计税价值；保留原预设名称、图片、材料、限购和任务条件。没有默认整枪报价时保留待估值，不能回退到裸机匣或虚构的配件合计。普通来源不足10条时展示琥珀色标签，不把报价数当成成交量。

7N42 30发包的源基础价为包装1000，所含弹药基础价400×30；整包计税价值为13000。原先仅用包装价，导致高挂价被误判为极端溢价。修正统一用于卡片、目标价试算、数量试算、历史净值和收益留档。数据源费率0.05/0.05、情报中心3级下，160000挂价在管理0级时税费25750，管理25级时22991、净到手137009；管理25级是核算示例，不是对用户实际技能的假设。该结果与用户“约23000”的实测量级一致，实际减免依其技能设置。净到手不等于扣除购买成本后的倒卖利润。

计算结构参考 [tarkov.dev 费率函数](https://github.com/the-hideout/tarkov-dev/blob/main/src/modules/flea-market-fee.mjs)和[其 API 舍入实现](https://github.com/the-hideout/tarkov-api/blob/main/resolvers/itemResolver.mjs)。包含内容的价值相加可由[SPT 的计税实现](https://github.com/sp-tarkov/server/blob/master/project/src/services/RagfairTaxService.ts)交叉核验；后者是独立实现，不能代替游戏内实测。武器预设的 basePrice 已含组件，不再重复相加。
