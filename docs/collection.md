# 后台行情采集

## 数据流程

`tarkov.dev → 源数据缓存 → 行情快照 → 历史摘要 / 配对收益档案 → 看板`

本机进程启动时预热缓存，此后每5分钟采集 PVE、PVP 常规、PVP 赛季。云端访问过期看板时返回旧快照，并在后台触发更新；刷新租约避免多个访客重复采集。独立托管采集计划目前停用。

`GET /api/dashboard?market=pve` 返回同一批行情、历史判定摘要和收益档案。首屏不下载所有原始历史；`GET /api/history?id=...&market=pve` 在物品明细需要走势图时读取。`/api/feed` 暂停公开，返回404。

## 缓存

| 数据 | 策略 |
| --- | --- |
| 行情快照 | 5分钟更新，失败保留上次成功值 |
| 基础中文资料 | 12小时缓存 |
| 单品历史 | 30分钟缓存，扫描按优先级分批推进 |
| 标签摘要 | 保留历史证据；过期短线证据不生成红色标签 |
| 配对收益 | 每小时至多一次，日汇总，包含亏损 |
| 看板 HTTP | 30秒缓存，支持 ETag 与条件请求 |

新行情先使用已有有效历史摘要发布，再在后台补齐扫描。缺少历史的物品保持中性；等待页面准备完成不代表所有上游物品都有足够历史。

## 手动核验

`GET /api/collect?market=pve` 请求刷新，同一市场5分钟内合并。其他市场为 `regular` 和 `pvp-season`。返回快照时间、历史覆盖数和异常信息。

`/api/health` 只证明服务存活。核验行情应读取看板的 `snapshot.fetchedAt` 与 `signals.checkedAt`；核验收益档案应读取 `/api/ledger`。错误不能把旧数据伪装成新时间。

QQBOT 在网站公测后再实现；本阶段不配置机器人、不绑定群、不发送消息。
