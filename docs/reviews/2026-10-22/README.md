# 三种玩家视角体验评审

2026-10-22，三个 GPT-6.1 Sol 子代理分别实际操作本地网站，按指定玩家画像模拟任务。报告用于提出迭代假设，不代表真人访谈、实战使用或游戏内成交验证。行情数字仅代表走查时的快照。

## 独立评价

| 视角 | 重点任务 | 报告 |
| --- | --- | --- |
| 萌新玩家 | 看懂金额、找物品、理解兑换和制作怎么执行 | [萌新入门](new-player.md) |
| 熟练跑刀玩家 | 战局瞥屏、杂物发现、图标云、预设和筛选 | [跑刀搜刮](scav-player.md) |
| 经营玩家 | 商人倒货、武器预设、制作成本与时间、条件设置 | [倒货与藏身处](economy-player.md) |

三个视角均实际访问四个主页面，并重点体验各自任务。收藏、详情、搜索、市场切换、酿酒、负收益路线分别有交互记录；未穷举所有物品或验证真实成交。各报告保留自己的观察与建议，下方是结合已有产品约束后的汇总取舍。

## 建议优先处理

| 优先级 | 观察与影响 | 迭代方向 | 验收方式 |
| --- | --- | --- | --- |
| P1 | MPL-50 标“卖 Jaeger”，但详情主数字仍呈现跳蚤回款，当前出售路径不明确 | 让出售渠道与对应净利成对展示，商人提示可展开看到报价和差额 | 卡片、详情的渠道与金额一致；玩家可按显示的成本、回款复算 |
| P1 | 314 钥匙明细离开列表后，缺少当前路线的商人、等级及限购上下文 | 在详情对应位置保留简短的“材料 → 商人兑换 → 出售”摘要 | 不返回列表也能找到当前路线的商人、材料数、条件与限购 |
| P2 | 跑刀手动取消饮食后，只能从数量变化察觉筛选状态 | “筛选”显示自定义状态或已改类别数，复用现有恢复默认按钮 | 默认、单独预设、自定义、收藏状态能清楚区分，重置可恢复 |
| P2 | “电池换新”等同名任务难以区分 | 先核查任务身份与分支，再补商人或分支短说明 | 同名不同任务可辨；不以合并名称误合并真实任务 |
| P2 | 净利、图标面积、底色需要玩家自行推断含义 | 在已有详情或帮助入口提供按需解释 | 萌新可找到解释；小卡继续保持图、名称、金额和底色为主 |

这轮证据支持“说明和执行上下文存在歧义”，尚不能据此认定交易公式错误。优先澄清显示口径，再用实际游戏案例验证。

## 对已有约束的取舍

- 保留用户指定的“净利/个”名称，必要解释放到按需帮助，不自动改名。
- 保留每批最终净利为制作默认排序；时薪只是参考，暂不增加新的排序与经营模式。
- 设施等级编辑建议与用户后续要求去除等级选项冲突，暂不采纳。不能将“当前没有等级选择”直接视为实现缺陷。
- 不重新增加卡片常驻备注、“满进度”副标题或 SPT 数据入口。小卡高值标记和大小说明建议需服从现有精简要求。
- 武器预设继续按基础整枪市场报价估值，不加配件收入；不引入拆件方案。
- 继续显示亏本倒货和制作，不计燃料，正式上线保持暂停。
