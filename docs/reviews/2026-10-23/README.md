## 已确认问题，按处理顺序

### 1. P2：跑刀云图更换搜索词后仍停在旧查询的滚动位置

- 代码：[app/app.js:260](C:/Users/ASUS/Documents/Codex/2026-10-20/new-chat/outputs/tarkov-profit-radar/app/app.js:260)、[app/app.js:270](C:/Users/ASUS/Documents/Codex/2026-10-20/new-chat/outputs/tarkov-profit-radar/app/app.js:270)。
- 触发：390×640，跑刀图标云搜索“钥匙”，浏览到初始 40 项结果末尾，再改搜“弹”。
- 子代理与主代理均独立复现：新查询首项已变为“弹药箱”，但内部滚动仍为 `1118.4px`。主代理测得结果区顶部为 `204px`，首项顶部为 `-903.6px`，用户直接看到新结果后段。
- 原因：本轮搜索改为全局 `state.search`，云图 key 仍只包含 `state.market`、`view()`、`state.density`。布局签名能确保结果项正确，但滚动归零仍只看这个 key 是否变化，因而漏掉换词。
- 影响：用户容易错过新查询的前列结果，尤其在手机上。
- 建议：将规范化搜索词加入 key，或仅在查询变化时重置云图滚动；同查询加载更多和行情更新继续保留阅读位置。
- 状态：**已修复并验证。** 云图 key 已加入去除首尾空格、转小写后的全局搜索词；查询变化会归零滚动，同一查询的行情更新和加载更多不改变 key。
- 修复复测：390×640 下，“钥匙”结果滚动到 `1118.4px` 后改搜“弹”，首项“弹药箱”回到可视区顶部，scrollTop 为 `0`；同一查询从 40 项加载到 80 项、点击刷新后，scrollTop 均保持 `1118.4px`。清空搜索恢复正常云图且滚动为 `0`。
- 修复后通过导航与云图 14 项相关测试、脚本语法检查、客户端及正式构建；未重复执行初次评审的 158 项完整测试。[修复效果](search-scroll-fixed.png)。
- [主代理复现截图](search-scroll-root-confirmation.png)；[交互独立报告](interaction-review.md)。

## 非阻断建议

1. **深色物品图的辨识度。** T7、Model 1、M-2 等暗面与统一深底接近，可试验克制的中性局部补光，保持透明图与统一底色；不恢复白底或金底。[视觉报告](visual-review.md)附现版截图。
2. **样式层叠的维护成本。** 同一组件在 `style.css`、`terminal.css` 与新 `archive` 层内仍有多套规则。当前覆盖顺序有效，不能将此直接判成布局故障；设计验收后再按组件整理，避免后续修改无效规则。交接文档仍有“terminal.css 最后加载”的旧说法，应同步当前顺序。
3. **交付检查盲区。** 现有资源测试主要覆盖指纹校验和 HTML 链接替换，不能发现真实 CSS 引用图片漏打包；可增加一项实际资源依赖完整性检查，不必为装饰样式逐条添加镜像测试。
