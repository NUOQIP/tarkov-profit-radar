数据量不含配对收益档案、图片和静态脚本；性能来自本机 Node 固定样本，不是公网首屏耗时或线上容量承诺。

## 调整

1. 将历史点整理为7日参照、近期复核点和逐日中位数。仍按玩家技能计算手续费，不能把统一税率的结果直接套给所有人。
2. 首屏一次读取行情、标签摘要及配对收益；详情原始走势图按需下载。
3. 删除传输中的未使用字段和非最优商人回收价，保留全部物品、进货路线及必要交易条件。
4. 后台采集与前台读取分开，过期缓存立即返回，重复更新通过租约合并。
5. 本机 gzip、ETag 和压缩结果复用；前端缓存同一物品的判定，市场切换取消旧请求。
6. 标签与列表准备完成后统一显示，失败提供重试；不增加人为最低加载时长。

## 准确性验证

使用优化前的模型逐条比较三个手续费条件，共4,161次历史判定，结果一致；全部物品的拾取、物品一览、倒货、制作收益在传输裁剪前后保持一致。

自动测试覆盖税费、预设枪、弹药包、材料与工具、亏损、活动、历史阈值、缓存更新、市场隔离与304响应。运行：`npm test`。

### 缓存分工

- 公共行情：IndexedDB只保存三个市场最近的公共批次，最多使用24小时的本机副本，后台重新核对。模型版本变化、损坏或越界缓存不采用。
- 程序：合并压缩JS/CSS，文件名含内容摘要，一年immutable缓存；HTML与后台程序重新验证，旧资源在切换时保留一版。
- 图片：浏览器缓存30天；服务器内存及磁盘复用、后台更新、请求合并和故障退避。跑刀小卡使用图标，中心大卡和明细使用大图；加载失败时尝试备用图片。
- 历史：独立64项LRU，避免图表把主行情挤出内存；旧图立即可读，后台只发起一次刷新。采集任务仍等待真实结果。
- 服务端：公共JSON共用编码字节缓冲，最多48MB；Brotli质量4与gzip双格式缓存最多16MB，合并同一批并发压缩。私密响应不复用，遵守编码质量与禁用设置。
- 私密数据：账号、条件、邮件配置、评论写入和后台响应no-store；不进入公共持久化或压缩缓存。
- 登录：90天Cookie与服务端期限一致，活跃时最多每天续一次，会话绝对上限一年；退出、改密码和过期仍有效。原30天内有效的会话可衔接。

复现：先运行 `node scripts/build-client.mjs`，再执行 `node scripts/benchmark-performance.mjs <旧版本解包目录>`。原始结果保存在 `work/performance-20261023.json`。测试：`npm test`；构建：`npm run build`；腾讯云运行包：`node scripts/package-update.mjs 20261023`。
