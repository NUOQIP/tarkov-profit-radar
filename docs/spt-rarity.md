# 跑刀稀有度与排序

## 数据

采用 [tarkynator 公开的 SPT 4.1+ 物品库](https://github.com/emilanderss0n/tarkynator/blob/9b490cfb1585e8a24e1a86941ec59a0a85b5dd1f/data/items.json)，版本提交于 2026-08-14，固定提交 `9b490cfb1585e8a24e1a86941ec59a0a85b5dd1f`。

读取 `_props.RarityPvE`，按游戏物品 ID 匹配。原库共 4,673 条：常见 591、稀有 1,287、超稀有 759；`Not_exist` 1,940、缺字段 96。后两种不推断为“局内不存在”，归入待补充参考项，不占常见好物区域。枪械预设优先匹配基础武器模板。

三个市场共用这份 SPT 稀有度参考，价格和短线信号分别计算。它是稀有度等级，不是官方在线服的地图刷出概率，不显示虚构百分比。玩家页面不展示 SPT 版本、来源标签和检查结果；特殊物品、地图和活动开关继续遵循现有独立规则。

仅打包 2,637 条有效等级及来源元信息，约 72 KB；浏览器不下载约 19 MB 的完整数据库。文件本地随应用发布，网络访问失败不会导致本轮稀有度缺失。

## 优先级

常见好物优先放在图标云中心，稀有和未收录物品缩小放在外围；不分栏。常见物品按以下得分排序，其他物品按单格净值排序；同分按物品 ID 保持稳定：

| 维度 | 权重 | 处理 |
| --- | --- | --- |
| 常见程度 | 50% | 常见 1、稀有 0.45、超稀有和未知 0.2；再乘 `min(1, 净值 / 30000)` |
| 单格净值 | 40% | `min(1, ln(1 + 净值 / 10000) / ln(101))`，100万封顶 |
| 短期涨价 | 10% | 命中涨价机会且涨幅为正时，`0.6 + 0.4 × min(1, 涨幅)`；否则为 0 |

这些是展示参数，不是刷率估计。未知项仍可见，管理员可以补充稀有度。常见组内的价值、涨价信号决定先后，稀有项无法凭高价占据大卡。

浏览推荐的门槛为单格净值 ≥30,000 卢布，恰好30,000保留，按未四舍五入金额判断。输入搜索后临时查找全物品，不受价值、类型预设和仅看收藏限制；仍保留活动开关及玩家交易条件。精确名称优先，搜索结果按需加载，清空或按 Esc 返回原筛选。无价格的物品显示破折号，不假造价格。

预设只改变临时显示类型，不改写用户选择。再次点击当前预设或「返回我的筛选」即可恢复；切换多个预设仍保留原选择。主动在筛选抽屉应用新选择才更新自定义条件。自定义类型按市场保存并参与账号同步，临时预设不跨设备同步。

跑刀筛选中的「无视跳蚤等级限制」默认勾选，取消后按实际等级估值；图标云、列表、明细使用同一口径。跳蚤禁售、活动开关及设施手续费始终生效，不修改玩家保存的等级。物品一览、倒货、制作仍按实际等级计算。

图标云按当前窗口生成矩形拼贴：先固定中心大卡，再递归分割剩余空间，每次分割完整覆盖原区域，避免空洞、重叠及细长碎片。越靠外围，目标面积越小；实际尺寸连续取整，视觉样式分五档。常见好物优先获得大卡，小屏保留少量稀有高值提醒。装不下的推荐不渲染，不向下追加；列表和搜索仍能查看其余物品。搜索结果使用等尺寸、相关度顺序排列，结果多时可继续加载。

所有卡片只保留图片、名称、单格价值和底色，窄长卡片使用左右排版。红色急涨优先于浅金长期高值。行情更新且候选集合、稀有度未变时保留位置；「重新排列」应用最新顺序。窗口、密度和筛选改变时重新排布。

## 更新

版本检查仅留在服务端，结果保留供以后管理后台查看；玩家页面不提供入口、不轮询检查状态。页底「排序优先级」说明展示三项权重和「≥3万 / 格」门槛；图标云不再显示底部数量与列表跳转行，顶部保留云 / 列表切换。

本机 / 腾讯云服务启动时检查，到期后每周再次检查；进程按小时检查是否到期，关闭网页后仍运行。托管 Worker 在计划采集时补做已到期检查。只查询 GitHub 上 `data/items.json` 的最新提交，不把上游网站代码改动算作物品库更新，也不下载完整物品库。

状态保存在 `spt/upstream.json`，重启保留；并发请求合并，服务端强制检查有共享的 10 分钟间隔。支持 ETag，失败保留上次成功结果，1 小时后自动重试；遇到限流遵守上游等待时间。版本变化只记录，不自动替换当前稀有度，不影响行情或跑刀排序。

内部模块 `app/spt-upstream.mjs` 提供 `readSptStatus` 与 `checkSptUpstream`，没有公开查询 / 操作接口。状态分别表示未检查、检查中、与上游一致、上游有变化、检查失败；成功检查时间与数据提交时间分别保存。

确认新版本后，传入新数据的完整提交号手动更新：

```sh
node scripts/update-spt-rarity.mjs <40位提交号>
node --test app/loot-priority.test.mjs app/quicklook.test.mjs
```

脚本校验物品 ID、最小数据规模和等级覆盖，记录来源与 SHA-256；更新后需检查版本说明、样本分类及数量断言，再构建发布。SPT 数据和游戏美术归原权利人所有。
