# 玩家账号与邮箱

玩家默认用邮箱＋密码登录，也可选择验证码登录，无需游戏账号。QQ、163、126、Outlook、Gmail、企业邮箱等均可使用；收件邮箱不受发信服务预设限制。

## 玩家使用

- 未登录可浏览、调整条件和收藏，数据保存在当前浏览器。
- 右上角「登录」或「我的条件」底部进入账号。默认「密码登录」，旁边保留「验证码登录」。
- 「注册账号」验证邮箱后设置8–128字符的密码；「忘记密码」通过邮件验证码重置。验证码10分钟有效，60秒后可重发。
- 验证码首次登录也可直接创建账号。已有账号在账号面板「设置密码」中补设，昵称、条件和收藏保持不变。修改密码同样需要邮箱验证，并让其他设备退出登录。
- 首次登录可导入本机设置或使用默认设置；已有账号默认恢复账号档案。
- 自动同步三个市场的等级、设施、商人、任务、收藏、筛选、外观和网格密度。当前页、搜索文字与暂停状态不跨设备同步。
- 网络中断时修改保留为本机草稿；恢复网络后重试。多设备冲突需选择保留版本，不静默覆盖。
- 已同步时收起同步操作，仅有待同步修改或冲突时显示对应选项。不提供常驻的「从本机导入」入口。
- 评论需要登录，昵称由账号提供。邮箱不显示在评论中。历史匿名评论继续保留，不自动认领。
- 登录保持90天；活跃时最多每天续期一次，同一会话最长一年。关闭浏览器、服务重启与正常更新保留登录；旧版本尚未过期的会话自动衔接。退出当前设备后恢复原访客设置，修改密码撤销其他设备的会话。

## 配置发信

在 Node 服务的 `/admin/` 登录，打开 **邮箱**：

1. 选择 QQ 邮箱、腾讯企业邮箱、163、126，或自定义 SMTP。
2. 填写发信账号和 SMTP 授权码。授权码在邮箱提供商的设置页开通，通常不是登录密码。
3. 启用验证码邮件，保存后「检查连接」。检查只验证连接和认证，不发送邮件。
4. 在玩家页面用自己的邮箱获取验证码，完成真实收件与登录验收。未配置时显示「邮箱服务待配置」，不会伪造发送成功。

自定义服务支持465直连TLS、587或25强制STARTTLS，始终验证证书。发件地址留空时使用发信账号；如另设地址，须由服务商允许代发。需要 OAuth 的服务不能直接使用普通密码，应使用服务商提供的 SMTP 凭据或另一个发信服务。[SMTP 配置参考](https://nodemailer.com/smtp)

发送后是否进入收件箱、垃圾箱或被拒收，仍由邮箱服务决定。公网启用前使用至少 QQ 和另一种常用邮箱做实际收件测试。

## 存储与保护

| 路径（相对 DATA_DIR） | 内容 |
| --- | --- |
| `community/accounts.sqlite` | 已验证邮箱、昵称、密码摘要、会话摘要、验证码摘要、条件与版本 |
| `community/comments.sqlite` | 评论、作者关联和管理状态 |
| `admin/mail.json` | SMTP 配置与授权码，文件权限0600 |

会话令牌只放入当前主机的 HttpOnly、SameSite=Strict Cookie，公网加 Secure；Max-Age 与 Expires 和服务器期限一致。续期只更新有效会话，不复活过期或已退出的会话。登录和写操作核对同源，已登录写入另校验CSRF。验证码绑定邮箱与用途，一次有效、最多5次尝试，不向客户端或日志返回验证码。限制邮箱、IP和全站发送频率。

浏览器的 IndexedDB 只缓存公共行情；条件草稿单独按账号保存，不缓存密码、验证码或会话令牌。会话、条件、邮箱配置与评论写入接口返回 `no-store`。价格读取省略账号 Cookie，公共压缩缓存不保存账号响应。

密码使用随机盐和异步 scrypt（N=32768、r=8、p=3）生成摘要，不存储明文；计算并发受限。密码登录另设邮箱、IP与全站限速，未知邮箱和错误密码返回相同提示。重置会撤销旧会话及验证码，已有账号数据通过兼容迁移保留。[Node.js 密码派生接口](https://nodejs.org/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback)

玩家条件按账号隔离，用版本号保护并发写入。后台邮件接口不返回授权码，保存时留空保留原码；更换账号或主机须重新填写。

每日备份包含账号库、评论库和私密管理配置；**管理备份含SMTP授权码**，不要放入公开仓库或共享下载。SQLite库用在线备份接口，不能只复制正在运行的 `.sqlite` 主文件。恢复前停止服务，保留旧库和WAL，核对所有者与权限后启动。

账号服务运行于腾讯云 / 本机 Node 服务。原 Sites 预览仅保留看板展示，不提供账号和邮件服务。
